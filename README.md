# AI-помощник для входящих заявок

Сервер принимает текст заявки, возвращает тему и черновик ответа. Менеджер читает результат и сам решает, что отправить клиенту.

## Запуск и тесты

Нужны Node.js 20 или новее, зависимостей и ключей нет. Из корня проекта:

```sh
node server.mjs
node --test
```

Страница открывается на http://127.0.0.1:3000; порт меняется переменной `PORT`.

## Что сделано

API `POST /api/triage` теперь отклоняет пустой, отсутствующий, нестроковый текст и битный JSON кодом 400 с `{"status":"invalid_input"}`. Ответ модели ждётся не дольше 300 мс и проверяется: JSON должен содержать тему из `delivery`, `pricing`, `other` и непустой черновик. Если модель ушла в таймаут, упала или вернула неподходящий ответ, API возвращает 200 с `{"status":"manual_review","topic":null,"draft":null}`. Поведение имитатора в `mock-ai.mjs` оставлено прежним.

Страница при успехе показывает тему и черновик. При `manual_review` и при некорректном вводе она показывает понятное сообщение и очищает предыдущий черновик, чтобы старый текст случайно не ушёл клиенту.

Результат AI проверяется в функции `askModel()` сервера `server.mjs`. Для проверки добавлен `triage.test.mjs`: он поднимает сервер на свободном порту и прогоняет обычный текст, все пять меток сбоя имитатора (`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`) и некорректный ввод.

AI при выполнении: Tencent Hunyuan Hy. Самостоятельно прогнан `node --test` — 7 тестов из 7; на исходном коде тот же набор даёт 6 падений из 7; живой HTTP-смоук через curl подтвердил коды 200 и 400.

## Польза для менеджера

Плохой ответ модели больше не попадёт в черновик для клиента: при сбое менеджер сразу видит ручной разбор. Измерить пользу можно долей заявок со статусом `ready` среди всех разборов.
